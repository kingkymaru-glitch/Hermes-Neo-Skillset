# Post-Submission Meeting Preparation

Use this checklist to prepare for client calls after submitting an RFI/RFP response.

## Pre-Call Check
- [ ] Proposal document is finalized and submitted
- [ ] All pricing is internally approved and consistent
- [ ] Live demo environment is ready and branded with primary system name
- [ ] Browser tab title/URL matches the client-facing brand, not internal platform names
- [ ] Key metrics from prior POC/case study are accessible

## Call Agenda
1. Pain restatement — confirm you understand the client's constraint in their language
2. System overview — ONE name, layered pipeline from field to AI
3. Proven experience — Effingham POC or equivalent with dates, locations, outcomes
4. Requirement mapping — walk 2-3 RFI requirements live to your deliverables
5. Phased path — pilot scope, timeline, and scale-up conditions
6. Commercial model — payment terms, flexibility, next steps

## Pitch Flow
- Open with the client's problem, not your product
- Present the layered architecture once, briefly
- Use the case study as evidence before quoting features
- Close with the two-path offer: pilot now, scale-up later

## Demo Rules
- Show only the primary-system branded interface
- Keep navigation to the layers the client asked about
- If showing a live dashboard, ensure no internal tabs/tools are visible
- Do not show internal platform URLs or repo names
- Have a fallback screenshot/video if live demo fails

## Attendee Roles
- Technical decision-maker: pipeline, integration, timeline
- Commercial decision-maker: pricing model, payment terms, contract structure
- Operations: daily workflow fit, alerting, training burden

## Anticipate
- "What if <technology X> is cheaper?" — focus on total ownership cost and proven operability
- "Can you start in <shorter timeline>?" — honest assessment of minimum viable pilot
- "What if <our sites> are different?" — reference the Effingham lessons learned and how the design handles variability
