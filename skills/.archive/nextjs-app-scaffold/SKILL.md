# Next.js App Router scaffold (create-next-app + Tailwind + shadcn/ui)

Procedure for a fresh Next 14 App Router + TypeScript + Tailwind + shadcn/ui app.

## Steps in order
1. **Repo dir name may be UPPERCASE (MARU repos: CDM, ARRAS...). create-next-app REJECTS it** because npm package names cannot contain capitals (`name can no longer contain capital letters`). Scaffold into a lowercase temp subdir, then move the contents up into the repo root:
   ```bash
   cd <repo>
   npx create-next-app@14 <lowercase-tmp> --typescript --tailwind --eslint --app --no-src-dir --import-alias "@/*" --use-npm --yes
   shopt -s dotglob && mv <lowercase-tmp>/* . && rmdir <lowercase-tmp>
   ```
   Then edit `package.json` `name` to the lowercase repo name (e.g. `cdm`).
2. **Init shadcn/ui**: `npx shadcn@<v2.3> init -d -y`. Then `npx shadcn add <components...>` for the ones the shell needs.
3. **Fix the shadcn 2.x oklch/hsl token mismatch** — shadcn 2.x writes `oklch(...)` color values into `app/globals.css` `:root`/`.dark` vars, but leaves `tailwind.config.ts` referencing them as `hsl(var(--x))`. `hsl(oklch(...))` is invalid → all theme colors break. Rewrite the config color map to reference the var BARE (`background: "var(--background)"`), not wrapped in `hsl(...)`.
4. **Add missing `--destructive-foreground`** to both `:root` and `.dark` in globals.css if shadcn didn't emit it — components like `button`/`badge` reference it and build/lint stay green but the color is undefined.
5. **Dark by default**: shadcn tokens are CSS-var-based; put `className="dark"` on `<html>` in `app/layout.tsx` (the `.dark` block holds the dark values). Body gets `bg-zinc-950 text-zinc-100`-style explicit backdrop.
6. **Fonts**: the stock create-next-app scaffold vendors Geist locally via `next/font/local` (`.woff` in `app/fonts/`) — do NOT `npm i geist` and import `geist/font/*`; that module won't resolve. Keep the local-font scaffold.
7. **Verify**: `npx tsc --noEmit` clean, then `npm run build` clean (a static route is fine), then grep `.next/server/app/index.html` for the panel markers to prove SSR markup shipped. Do NOT trust build-green alone if you later integrate a client-only heavy lib (Cesium/Three) — see `nextjs-client-heavy-lib-integration` for the octal-escape blank-page trap.
8. Avoid invalid Tailwind arbitrary classes like `h-4.5` (not a valid size) — use `h-4`/`h-5`.

## Pitfalls
- create-next-app inside an empty git repo is fine, but the package-name (from the dir) must be lowercase — hence the temp-dir dance for uppercase repos.
- `.gitignore` generated by create-next-app ignores `.env*.local` but NOT a bare `.env` — add `.env` if you'll ever use one.
- Keep the stack on the approved list (Next App Router + TS + Tailwind + shadcn/ui + Lucide); don't import an unapproved lib as the first scaffold step.
