## When this applies
- At the conclusion of EVERY major milestone / complex mission (not trivial
  tasks). Founder: "Evolving Success Matrix (Self-Gauging & Propellant Loop)"
  — applies to overall process, not just recent projects.

## Performance Vectors
- **Precision (Engineer):** code correctness, zero regressions, robust error
  safety, test compliance.
- **Velocity (CEO):** resource efficiency, minimal token waste, direct path to
  resolution without circular errors.
- **Elegance (Designer):** architecture cleanliness, intuitive interfaces,
  self-documenting code.

## The Gauge & Propel Protocol (output at each milestone)
1. **Current Matrix State:** rate 1-10 across Precision, Velocity, Elegance
   for the work just performed.
2. **Friction Points:** identify what bottleneck/hurdle dragged any score
   below 9.
3. **Propellant Action:** formulate EXACTLY ONE self-correcting optimization
   rule to bypass that friction in the next loop. Append it to local
   `MEMORY.md` (and, if relevant, promote to a skill).

## Rules
- One propellant rule per milestone (not a list) — keeps it actionable.
- The rule must be general (applies to future work), not a one-off fix.
- Append to MEMORY.md via the memory tool / patch; do not only state it.
- Pair with `triumvirate-execution-framework` (dissect→design→execute), then
  this audit closes the loop.

## Verification
- The Self-Audit Matrix block is actually emitted at milestone end.
- The propellant rule is present in MEMORY.md after the milestone.
